# OCR 段落文案识别准则

## 1. 文档目的

本准则用于指导 UI 文案优化工具对界面截图进行 OCR 检测、版面分析、段落组合与候选文案筛选。

识别目标不是单独的文字行，也不是 OCR 引擎默认返回的段落，而是视觉上属于同一容器、语义上连续、可以作为一个整体进行文案优化的 UI 文案块。

标准处理链路：

```text
单词识别 → 文本行拆分 → 页面分区 → 区内段落组合 → UI 类型判断 → 大模型语义校验 → 输出待优化文案
```

## 2. 总体原则

1. 先拆分，再组合：先修正 OCR 错误合并的文本行，再判断是否组成段落。
2. 先分区，再合并：跨栏目、跨容器、跨控件的文字不得合并。
3. 视觉关系优先：位置、容器、行距、对齐和文字样式是段落组合的基础。
4. 语义判断兜底：大模型负责校验语义连续性和文案类型，不替代基础版面分析。
5. 不确定时优先拆分：错误拆分可以在后续重新组合；错误合并会同时破坏页面理解、文案优化和框选位置。
6. 当前任务焦点优先：模态框、抽屉、浮层等临时界面出现时，只识别当前焦点容器内的文案。
7. 模块边界优先于文字关系：任何语义、对齐或行距规则都不能覆盖明确的栏目、卡片和控件边界。

## 3. 识别范围与焦点层级

系统必须先确定当前页面的交互焦点，再进行文字分组和候选筛选。

界面层级优先顺序：

```text
模态框 / 对话框 > 抽屉 / 浮层 > 当前内容容器 > 页面背景
```

### 3.1 模态框识别特征

满足以下多项特征时，应判定页面存在模态框：

- 页面大部分区域覆盖统一的半透明蒙层或整体亮度、饱和度明显降低。
- 蒙层上方存在边界清晰、对比度更高的矩形或圆角容器。
- 容器通常位于视口中部或视觉中心附近。
- 容器内部包含标题、正文、关闭图标和确认、取消等操作按钮。
- 背景内容仍可见，但呈弱化、不可操作状态。

### 3.2 模态框焦点隔离规则

判定存在模态框后，以下规则为最高优先级硬规则：

- 只对模态框边界内部执行 OCR 文案筛选和段落组合。
- 模态框外的页面标题、导航、提示、表格、按钮和其他文字全部标记为不参与优化。
- 不得将模态框文字与蒙层外文字合并。
- 模态框内标题、正文、辅助说明和按钮分别识别，不互相合并。
- 如果无法精确确定模态框边界，应使用高对比度前景容器的最小外接矩形，并适当向内收缩，宁可漏掉边缘文字，也不得识别背景内容。
- 只有用户明确选择“同时分析背景页面”时，才允许恢复对模态框外内容的识别；阶段 1 默认不提供该能力。

### 3.3 抽屉和非模态浮层

- 存在蒙层的抽屉按模态框规则处理，只分析抽屉内部。
- 不存在蒙层的浮层，应将浮层和页面主体视为两个独立区域，禁止跨区域合并。
- 下拉菜单、日期选择器、气泡提示等临时浮层出现时，优先识别浮层中的说明和状态文案，背景内容保持独立。

## 4. 文本行拆分规则

OCR 可能把同一水平位置、但位于不同区域的文字识别成一行。系统必须根据单词坐标和视觉结构重新拆分。

满足以下任一条件时，应拆分为两个文本块：

- 相邻词语的水平间距超过平均字符宽度的 2.5～3 倍。
- 两部分之间存在输入框、图片、边框、分割线或大面积空白。
- 两部分位于不同页面栏目或不同视觉容器。
- 左侧是字段名称，右侧是字段值、选择结果或用户输入内容。
- 前后文字无法组成连续语句。
- 两部分的字体、颜色、字号或背景明显不同。
- 识别框穿过明显的竖向分栏线、侧边栏边界、内容画布边界或表单容器边界。
- 同一文字行内部存在一个或多个宽度明显大于正常词间距的“空白谷”。

示例：

```text
图像参数                         镜像模式
```

必须拆分为“图像参数”和“镜像模式”，不能生成横跨页面的识别框。

### 4.1 跨区域大框判定

满足以下任一条件的 OCR 文本块，应判定为异常大框，必须尝试拆分：

- 同时覆盖两个或以上已识别页面区域。
- 穿过侧边栏与主内容区、预览区与表单区等明确结构边界。
- 横向宽度超过页面宽度的 35%，但文字实际分布不连续。
- 文本块内部最大水平空白超过平均字符宽度的 3 倍。
- 外接框内的有效文字面积占比过低，包含大量无关空白。
- 同一框内同时出现菜单名称、说明文案、字段标签或参数值等不同 UI 类型。

异常大框处理顺序：

1. 按页面区域边界切分。
2. 在各区域内部按单词坐标和空白谷继续切分。
3. 对切分结果重新执行行组合与语义判断。
4. 如果缺少单词级坐标、无法可靠拆分，该大框直接标记为无效，不得参与优化。

禁止为了避免漏识别而保留跨区域大框。漏掉一个低置信度候选优于错误框选多个业务模块。

## 5. 页面分区规则

在段落组合之前，应根据位置、背景、边框、分割线、留白和控件结构划分页面区域。

常见区域包括：

- 顶部导航栏
- 一级侧边栏
- 二级侧边栏
- 内容预览区
- 参数表单区
- 卡片
- 弹窗或抽屉
- 表格
- 提示区域
- 底部操作区

以下为硬性规则：

- 不同页面分区的文字不得合并。
- 不同卡片或容器的文字不得合并。
- 弹窗内容不得与背景页面内容合并。
- 左右两栏文字不得因为纵坐标相近而合并。
- 不同表格单元格、不同表格行之间不得合并。
- 不同表单项的文字不得合并。
- 预览画布中的提示文案不得与画布外的菜单或参数表单合并。
- 页面中的竖向分割线、背景色切换和容器留白应视为强边界，其优先级高于左对齐、横向重叠和语义连续性。

### 5.1 原子模块规则

页面分区后，还需识别不可跨越的原子模块：

- 单个菜单项
- 单个表单项
- 单个提示容器
- 单个表格单元格
- 单个卡片
- 单个弹窗内容区
- 单个预览画布

段落只能在同一个原子模块内形成。即使两个模块中的文字字号、颜色、行距和对齐完全一致，也不得合并。

## 6. 多行文字合并规则

两行文字只有同时满足空间关系、容器关系、样式关系和语义关系时，才能合并为同一段落。

### 6.1 行间距

行间距是上一行文字底部到下一行文字顶部之间的净空白。

- 净空白不超过平均文字高度的 0.5～0.6 倍时，可以继续判断。
- 净空白达到平均文字高度的 0.8 倍时，默认断段。
- 净空白超过一行文字高度时，强制断段。
- 具体阈值可随截图缩放比例和 OCR 字符高度自适应，不应使用固定像素作为唯一依据。

### 6.2 容器关系

两行文字必须属于同一个视觉容器，例如：

- 同一提示区域
- 同一弹窗正文
- 同一卡片
- 同一表单帮助说明
- 同一表格单元格
- 同一内容面板

跨越容器边界时，无论行距多小都不得合并。

### 6.3 对齐和横向关系

两行应满足以下至少一项：

- 左边缘基本对齐。
- 第二行存在合理的段落缩进。
- 第一行为列表符号，第二行为同一列表项的换行内容。
- 两行横向范围存在至少 50% 的有效重叠。

左对齐只能作为辅助依据，不得单独决定合并。

### 6.4 文字样式

两行以下特征应基本一致：

- 字号
- 字重
- 颜色
- 行高
- 背景
- 对齐方式

标题与正文、字段名与字段值即使相邻，也不能自动合并。

### 6.5 语义连续性

满足以下情况时，可以提高合并置信度：

- 上一行没有形成完整语义，下一行明显是续写。
- 两行组合后形成完整句子。
- 同一列表项因为容器宽度发生换行。
- 前后存在自然的语法或标点衔接关系。

示例：

```text
安装播放控件才能正常播放实况，点击下载安装。如已经安装，
请重启浏览器。
```

应识别为一个段落。

## 7. 强制断段规则

满足以下任一条件时，不得合并：

- 行间距明显大于自然行距。
- 位于不同栏目、卡片、表格单元格或表单项。
- 上一行是标题，下一行是正文。
- 两行属于不同按钮、菜单项、页签或字段标签。
- 两行分别是字段名称和字段值。
- 中间存在分割线、边框、图标、输入框或明显背景变化。
- 上一行语义已经结束，下一行开启新主题。
- 字号、颜色、字重或对齐方式差异明显。
- 两行属于不同列表项。
- 任意一行横跨多个页面区域且无法确认属于同一容器。
- 当前存在模态框，但文字位于模态框边界之外。
- 两行之间跨越侧栏、画布、表单或卡片等原子模块边界。
- 合并后的外接框包含大面积无文字空白，或宽度显著大于实际连续文字范围。

## 8. 常见 UI 场景规则

### 8.1 弹窗

分别识别：

- 弹窗标题
- 正文说明段落
- 列表项
- 操作按钮

标题、正文、列表项和按钮不得互相合并。

当弹窗带有蒙层时，弹窗外所有文字默认不进入候选集合，包括背景页面中原本可能需要优化的说明文案。

### 8.2 表单

分别识别：

- 字段名称
- 当前值
- 占位提示
- 帮助说明
- 错误提示

字段名称不得与输入内容合并。同一帮助说明中的多行文字可以合并。

### 8.3 表格

- 同一单元格内的自然换行可以合并。
- 不同单元格不得合并。
- 不同表格行不得合并。
- 表头与数据内容不得合并。

### 8.4 菜单和导航

- 每个菜单项、页签和导航项独立识别。
- 上下相邻的菜单项不得进行段落合并。
- 图标不得纳入文字框范围。

### 8.5 提示、说明和免责声明

同一提示容器内，样式一致且语义连续的多行文字，应优先合并为一个段落。这类内容是阶段 1 的核心优化对象。

## 9. 待优化文案筛选规则

段落识别完成后，系统还需判断文案是否参与优化。

### 9.1 优先参与优化

- 功能说明
- 状态说明
- 操作提示
- 异常提示
- 风险提示
- 限制条件
- 免责声明
- 帮助说明
- 空状态说明
- 弹窗正文
- 较长的操作确认说明

### 9.2 默认不参与优化

- Logo 和品牌名称
- 菜单名称
- 页面标题
- 表格列名
- 单纯字段名称
- 数字、日期和时间
- 用户输入的数据
- 型号、协议、分辨率等固定参数
- 单纯按钮名称
- 技术配置值

大模型可以结合页面上下文调整分类，但需要返回分类结果、判断依据和置信度。

在筛选之前必须先执行以下否决条件：

- 位于当前模态焦点之外：否决。
- 文本框跨越两个或以上页面区域：否决。
- 无法从跨区大框中可靠恢复单一段落：否决。
- 同时包含两种以上 UI 类型且无法拆分：否决。
- 框内存在大面积无关空白或无关控件：否决。

## 10. 置信度模型

每个候选段落应计算综合置信度：

| 判断维度 | 建议权重 |
| --- | ---: |
| OCR 文字准确度 | 30% |
| 同一容器可信度 | 25% |
| 行距与对齐关系 | 20% |
| 文字样式一致性 | 10% |
| 语义连续性 | 15% |

建议处理方式：

- 综合置信度 ≥ 0.8：直接组成段落。
- 综合置信度为 0.6～0.8：交给大模型校验。
- 综合置信度 < 0.6：保持拆分，不主动合并。

置信度不能推翻硬规则。即使 OCR 和语义置信度很高，只要跨越模态框边界、页面分区或原子模块边界，就必须断开或淘汰。

## 11. 输出要求

每个最终文本块至少应包含：

```ts
type RecognizedTextBlock = {
  id: string;
  text: string;
  bbox: { x: number; y: number; width: number; height: number };
  regionId: string;
  uiType: string;
  confidence: number;
  shouldOptimize: boolean;
  reason: string;
};
```

界面展示规则：

- 仅 `shouldOptimize = true` 的文本块显示蓝色虚线框。
- 一个完整段落对应一个框。
- 框不得跨越页面分区或包含无关控件。
- 优化结果继续使用同一个框的位置，不重新计算布局范围。
- 存在模态框时，所有输出框必须完全位于模态框边界内部。
- 输出框不得跨越已识别的页面区域和原子模块边界。

## 12. 验收标准

OCR 段落识别至少需要通过以下检查：

1. 同一说明文案的自然换行不会被逐行框选。
2. 间距较大的独立文案不会被合并。
3. 左右两栏同高度文字不会形成横跨页面的框。
4. 菜单、字段名和参数值不会被错误合并。
5. 弹窗内容不会与背景页面内容合并。
6. 表格识别范围不跨单元格和表格行。
7. 提示、限制说明和免责声明能够作为完整段落识别。
8. 框选区域不包含图标、输入框或大面积无关空白。
9. 参与优化与不参与优化的文案分类符合页面业务语义。
10. 存在模态框时，模态框外不出现任何待优化框。
11. 侧栏、预览画布和参数表单之间不出现横跨多个模块的大框。
12. 无法可靠拆分的跨区 OCR 结果会被淘汰，而不是作为一个段落展示。

## 13. 阶段 1 实施策略

阶段 1 应优先减少错误合并，不追求对所有特殊排版进行自动合并：

1. 首先检测模态框、蒙层、抽屉和当前焦点区域。
2. 优先实现基于单词坐标的超长文本行拆分。
3. 实现基础页面分栏、原子模块和容器边界判断。
4. 只在同一区域、同一原子模块内部进行段落聚类。
5. 使用大模型完成语义连续性和待优化文案筛选。
6. 对低置信度结果保持拆分，不显示不可靠的大范围框选。
7. 无法拆分的跨区大框直接淘汰，不允许进入优化候选。

本准则后续应结合真实截图测试集持续调整阈值，并分别记录错误合并、错误拆分、漏识别和错误分类四类问题。

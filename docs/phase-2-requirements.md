# 阶段 2 需求说明文档

版本：v1.0  
状态：已确认，待实现  
适用项目：UI Copy Lens（界语）

## 1. 需求背景

阶段 1 已经完成截图上传、OCR 识别、页面理解、候选文案框选和 AI 文案优化。当前工具可以生成结果，但用户仍需要在以下场景中进行额外操作：

- 优化后的文案需要复制到设计稿或其他产品中；
- 右侧设置面板占用画布空间，用户希望专注查看截图和结果；
- OCR 或大模型偶尔会多识别、少识别或错误合并段落，需要人工修正；
- 某一条文案不符合预期时，只能重新优化全部结果；
- 当前 OCR 和页面理解耗时较长，等待过程不够高效。

阶段 2 的目标不是扩展更多任务类型，而是建立“AI 识别—人工修正—单条使用”的结果处理闭环。

## 2. 产品目标

### 2.1 核心目标

1. 让用户可以快速复制单条优化文案；
2. 让用户在隐藏设置面板后仍能理解当前处理状态；
3. 允许用户修正 OCR 或模型造成的框选错误；
4. 允许用户只针对单条文案进行二次优化；
5. 缩短重复识别和等待时间，并让失败具备局部恢复能力。

### 2.2 非目标

阶段 2 不实现：

- 多图片或多页面上传；
- 全部结果批量复制；
- 复制格式选择；
- Figma 设计稿获取与文案回填；
- 历史记录、账号体系和多人协作；
- 复杂的文案结果状态管理。

## 3. 用户与使用场景

主要用户仍为 UI 设计师、产品设计师和负责 B 端系统体验的设计人员。

典型场景：

1. 用户完成截图优化后，将某一条结果复制到设计稿中；
2. 用户希望扩大画布查看结果，因此收起右侧设置面板；
3. 用户发现一个识别框包含了两个模块，进入编辑态拆分或重新框选；
4. 用户发现某条文案表达不准确，在文案附近补充临时要求并重新生成；
5. 用户对同一张图再次识别，希望复用已有 OCR 结果，减少等待时间。

## 4. 功能需求

### 4.1 单条优化文案复制（P0）

#### 功能描述

每条已生成优化结果的文案附近提供复制入口，用户可以单独复制当前优化文案。

#### 交互要求

- 只有存在优化结果时显示“复制”入口；
- 点击复制后，将当前优化文案写入系统剪贴板；
- 复制成功后显示轻量反馈：“已复制”；
- 复制失败时提示用户手动选择或重试；
- 不支持复制全部结果；
- 不支持复制格式选择；
- 复制内容只包含优化后的文案，不包含原文、编号或额外说明。

#### 异常处理

- 浏览器不支持剪贴板权限时，显示“无法自动复制，请手动选择文案”；
- 剪贴板权限被拒绝时，不影响当前优化结果和其他功能。

### 4.2 优化设置面板收起与恢复（P0）

#### 功能描述

用户可以收起右侧“优化设置”面板，让画布使用更大的可用空间；也可以随时恢复面板。

#### 收起后要求

- 左侧画布自动扩展并自适应剩余空间；
- 截图保持原始比例，不裁切；
- 保持当前缩放比例、平移位置和高亮状态；
- 画布中的识别框和优化结果位置不漂移；
- 页面顶部中央显示当前任务状态；
- 页面右下角保留“打开优化设置”入口；
- 已填写的补充要求、风格选择和结构化业务答案不丢失。

#### 顶部任务状态

状态文案至少覆盖：

| 状态 | 示例文案 |
| --- | --- |
| 空状态 | 请上传图片开始分析 |
| 识别中 | 正在识别界面文字 |
| 页面理解中 | 正在理解页面并筛选待优化文案 |
| 分析完成 | 解析成功，待优化 2 条 |
| 信息不足 | 信息不足，请补充业务信息 |
| 识别失败 | 识别失败，请重新分析 |
| 优化中 | 正在生成优化文案 |
| 优化完成 | 优化完成，已生成 2 条结果 |
| 已取消 | 已停止分析，图片已保留 |

状态文案应来自真实任务状态，不允许在任务失败时显示“解析成功”等误导信息。

#### 面板恢复

- 点击“打开优化设置”恢复右侧面板；
- 恢复后保留收起前的滚动位置和表单内容；
- 如果当前需要补充业务信息，恢复面板后直接定位到补充信息区域。

### 4.3 识别结果人工修正（P1）

#### 功能描述

用户可以对阶段 1 生成的候选框进行必要修正，以处理多识别、少识别、框选不完整或段落合并错误。

#### 进入编辑态

- 提供“编辑识别结果”入口；
- 进入编辑态后，所有当前候选框显示可操作边界；
- 非编辑态继续保持阶段 1 的查看和原文切换逻辑；
- 用户退出编辑态前，如果存在未确认修改，应提示保存或放弃。

#### 支持的操作

1. **删除**：删除误识别或不需要优化的候选框；
2. **调整边界**：拖拽已有框的边缘或角点，修正范围；
3. **重新框选**：重新绘制已有区域的范围；
4. **新增框选**：在画布空白位置拖拽创建新的文案区域，并触发局部 OCR；
5. **合并区域**：将多个属于同一自然段的区域合并为一个候选；
6. **拆分区域**：将包含多个模块或多个自然段的大框拆分为多个候选。

#### 文案状态视觉规则

- 待优化、已修改、待确认：统一使用蓝色虚线框；
- 优化失败：使用红色框；
- 未参与优化、已删除：不显示框；
- 不增加“待确认”“已修改”等独立的复杂状态标签。

#### 编辑后的处理

- 调整框选范围后，使用框内文字作为该候选的识别文本；
- 新增或重新框选后，只对该区域执行局部 OCR，不重新识别整张图片；
- 合并后按自然阅读顺序重新组成原文；
- 拆分后每个区域单独进入待优化列表；
- 删除后，该候选不参与后续优化，也不显示在画布上；
- 用户点击“保存修改”后，右侧待优化数量同步更新。

### 4.4 单条重新优化（P1）

#### 功能描述

用户选中某条文案后，可以在当前文案附近输入本次临时要求，只重新生成该条结果。

#### 交互流程

1. 用户点击一条已优化文案；
2. 当前文案进入选中态，附近显示临时要求输入框；
3. 用户输入本次优化要求；
4. 点击“重新优化”；
5. 系统只提交当前文案、全局页面理解、全局补充要求、风格选择和临时要求；
6. 返回后只替换当前文案，其他文案结果保持不变。

#### 规则

- 临时要求只对当前单条文案生效；
- 临时要求不覆盖右侧面板的全局补充要求；
- 关闭输入框或取消后，不改变当前优化结果；
- 单条优化失败时，当前结果保留，显示红色失败框和“重试”；
- 单条重新优化过程中，其他文案仍可查看，但不可重复提交同一条请求。

### 4.5 识别速度与稳定性优化（P1）

#### 性能策略

- 缓存当前图片的 OCR 结果；
- 同一图片再次识别时复用 OCR，不重复执行本地 OCR；
- 图片上传、OCR 和页面理解尽量并行执行；
- 上传前生成适合模型分析的图片版本，避免无必要的大图传输；
- 对 OCR、页面分析和单条优化分别设置超时和重试；
- 模型失败时不重复 OCR；
- 失败后保留图片、OCR 结果和已生成的候选结果。

#### 进度反馈

进度至少展示：

1. 读取图片；
2. 识别文字；
3. 理解页面；
4. 筛选候选；
5. 生成优化文案。

进度提示必须与实际阶段一致，不使用虚假的百分比。

#### 目标指标

- 同一图片再次识别不重复 OCR；
- 识别失败后可局部重试，不要求重新上传；
- 识别过程可取消，取消后图片和已有结果保留；
- 在相同网络和模型配置下，重复识别等待时间应明显低于阶段 1；
- 页面不因缓存命中而显示过期候选或其他图片的结果。

## 5. 业务流程

### 5.1 阶段 2 主流程

```text
上传图片
  ↓
OCR / 页面理解 / 候选筛选
  ↓
展示待优化候选
  ├─ 收起设置面板 → 顶部显示当前状态 → 继续查看画布
  ├─ 编辑识别结果 → 保存人工修正 → 更新候选
  └─ 一键优化
       ↓
  展示优化结果
  ├─ 单条复制 → 显示“已复制”
  ├─ 单条重新优化 → 输入临时要求 → 替换当前结果
  └─ 收起设置面板 → 顶部显示“优化完成”
```

### 5.2 识别结果修正流程

```text
进入编辑识别结果
  ↓
删除 / 调整边界 / 新增框选 / 合并 / 拆分
  ↓
局部 OCR 或重新组合原文
  ↓
保存修改
  ↓
更新候选数量和画布高亮
```

## 6. 数据与状态要求

每个文案候选至少包含：

- 唯一 ID；
- 原文；
- 优化文案；
- 画布坐标；
- 当前是否参与优化；
- 当前是否优化失败；
- 来源图片标识；
- 可选的单条临时要求。

删除候选后不再参与优化，但阶段 2 不要求建立删除历史记录。

## 7. 验收标准

### 7.1 复制

- 单条复制入口位置明确；
- 点击后剪贴板内容与当前优化文案完全一致；
- 成功显示“已复制”；
- 权限失败有明确提示，不影响页面继续使用。

### 7.2 面板收起

- 收起后画布自动扩展；
- 顶部状态与真实任务状态一致；
- 收起和恢复不丢失表单、缩放、平移和高亮状态；
- 失败、信息不足、完成等状态均可在面板收起后区分。

### 7.3 结果修正

- 能删除误识别框；
- 能调整、重新框选、新增区域；
- 能合并和拆分区域；
- 修改后候选数量、优化请求和视觉框同步更新；
- 删除项和未参与优化项不显示框。

### 7.4 单条重新优化

- 只能替换当前选中的一条结果；
- 临时要求不覆盖全局要求；
- 其他结果不被重置；
- 失败后当前结果仍可重试或继续查看。

### 7.5 性能与稳定性

- 同图再次识别命中 OCR 缓存；
- OCR、模型分析和单条优化可分别失败和重试；
- 取消后不出现旧请求覆盖新结果的问题；
- 连续切换和重复操作不会串用其他图片的候选数据。

## 8. 阶段 3 边界

以下需求明确留到阶段 3：

- 多图片上传和多页面任务管理；
- 多图批量处理和进度管理；
- 全部优化文案复制；
- 复制格式选择；
- 从 Figma 获取设计稿；
- 将优化文案回填至 Figma；
- 设计稿图层与文案候选的结构化映射。

### 9.1 已确认的交互细节

- 已识别或已生成文案框：右键选中，显示黄色选中框与“复制 / 编辑”浮层；点击画布空白处取消选中并隐藏浮层。
- 识别范围编辑：普通点击已有框进入范围编辑；黄色框只提供上、下、左、右 **4 个**拖拽手柄，不提供四角手柄。
- 调整范围后点击空白处确认，并立即仅对该区域执行 OCR；新增框在鼠标松开后立即执行局部 OCR。
- 临时优化输入框点击空白处只关闭且丢弃未发送输入；仅点击发送按钮才执行局部优化。
- 本轮人工修正实现删除、四向调整与新增框选。合并/拆分尚无确认交互稿，暂不实现，保留至后续补充设计后处理。

### 9.2 实施顺序

1. 建立候选框选中、局部处理中、局部失败与编辑范围的共享状态；统一缩放和全屏下的坐标换算。
2. 实现 P0 单条复制与弱提示，接入 Figma 对应图标资源。
3. 实现 P0 设置面板收起、恢复入口、画布自适应与顶部真实任务状态。
4. 实现 P1 人工修正：选择、四向调整、删除、新增框选和局部 OCR。
5. 实现 P1 单条重新优化：临时输入、单条接口请求、局部加载和失败恢复。
6. 复用同图 OCR 结果，补充取消、超时和并发保护；以缩放、全屏、面板收起组合场景回归验证。
7. 运行类型检查、现有自动测试、生产构建和一次界面验收。
